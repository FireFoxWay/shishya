01What this is

Shishya (शिष्य — student, apprentice) is a local AI workspace. You give it documents, talk to it in plain language, and it decides how to answer: read the material, build a spreadsheet, draft a document, assemble a deck, or write and run a program. All of it happens on one laptop, inside a virtual machine whose network is off by default.

Three things it is not

  • It does not train. It reads and indexes. No weights change. Say "it reads everything you give it" — the true answer is better than the impressive one, because you can add a document and have it answered from thirty seconds later, which real training could never do.
  • It is not an autonomous agent. One decision per turn, then a known code path. A model this size left to run a multi-step loop wanders: it calls a tool, misreads the result, and three steps later is confidently doing the wrong job.
  • It is not a cloud product. There is no server. Everything is one Mac.

02The argument

Staff everywhere paste confidential records into cloud AI to get their work done. Once that leaves the building you do not control it and cannot audit it. Shishya does the same work with nothing leaving the laptop — provably, because you can switch the network off and watch it continue — and every action is written to an append-only ledger, including the ones it was refused.

The distinction that carries the pitch

Automating clerical work is crowded. The uncommon part is not the automation — it is the sandbox, the audit ledger, the network lock and the undo button. Those are an argument about how AI should be permitted to operate. Lead with those; the automation is the demonstration, not the claim.

The single best result the project has produced

Asked which suppliers a pharmacy buys most from, it discovered that KK ENTERPRISES (9,602 rows) and Kk Enterprises (1,415 rows) are the same supplier counted twice — as are PATWARI PHARMA PVT LTD and Patwari Pharma Pvt Ltd, and 24 others. Nobody asked it to look. That is the difference between doing the filing faster and being useful, and it is the story to tell.

Strategy

You cannot win on the agent. Stop treating demonstration-learning as the differentiator — it became table stakes on 11 August. You are not building a worse Grok Bot; you are building the version for people who legally or financially cannot use it: a school holding children's records, a pharmacy holding prescription data, a district office. Ten staff on Grok Bot is $14,400 a year before anyone asks where the data went.

Use them in the pitch: "xAI launched this category three weeks ago at $120 a seat, in their cloud, with your passwords. Here is the version a government school can actually deploy." A frontier lab entering the space proves the market exists and removes the burden of explaining why it matters.

04Architecture

Two machines on one laptop, meeting at exactly three points.

  THE MAC (host)                  │      THE SANDBOX (Lima VM, Ubuntu 24.04)
                                  │
  browser → localhost:8200        │  Xvfb :0 (1440×900) → openbox → desktop.py
        ↕                         │      ↕
  serve.py   (stdlib only)        │  18 apps: chat, findings, training, code…
        ↕                         │      ↕
  host/vm.py    → limactl         │  AT-SPI accessibility bus
  host/ledger.py → var/*.jsonl    │      ↕
  host/synth.py  → procedures     │  x11vnc :5900 → websockify :6080
        ↕                         │
  Ollama (gpt-oss:20b, GPU)       │  nftables: DROP egress except the model
                                  │
  ───────────── three crossings ──┼─────────────────────────────────────────
     :6080   the clone's screen, into an iframe on the panel
     :11434  the model, reached from inside at host.lima.internal
     virtiofs  shared/ — the only writable window between them

Why each piece sits where it does

  • The model runs on the host. Inside the VM it would fall back to emulated CPU and be far too slow to demonstrate. On the host it uses the Apple Silicon GPU.
  • The mount list is the security model. The clone cannot read ~/Documents because it is not mounted — not because code checks a path. Grant a folder by adding a line to vm/lima.yaml; revoke it by deleting the line.
  • The clone has no sudo. Even inside the sandbox the agent is unprivileged, so failures stay small and it cannot lift its own network lock.
  • The panel binds to both loopback addresses only. It can start programs inside the sandbox; bound to every interface it would be reachable by anyone on the same wifi.
  • Snapshots are APFS clones. limactl snapshot is unimplemented for the vz driver. cp -c clones a 3.2 GB disk in about four milliseconds and costs no space until blocks diverge.
  • Everything is driven from the panel. Clicking inside the sandbox has failed repeatedly; the panel reaches apps through AT-SPI and signals, which never has.

07How it decides

Each turn is one decision, then a known code path. Six actions: answer, spreadsheet, document, deck, code, clarify.

The shortcut comes first

The model reads requests well and holds a six-way choice badly. Asked twice whether "can a student with 68% attendance sit the exam" was a question, it answered clarify once and spreadsheet the other time — a question it answers well, routed first to a refusal and then to a file.

So the shapes that are unambiguous in English are settled in English, before the model is consulted:

  • Counting words (how many, total, average, most, rank…) and not a making verb → code
  • Ends in "?" or starts with can/is/does/what/which/who/how, and not a making verb → answer
  • Anything else → ask the model with a constrained JSON schema

Eight of eight test requests route as intended, and the common ones never reach the model at all.

08How it finds material

Documents are read to text, split into overlapping 1,400-character windows, indexed by term with rarity weighting. Spreadsheets additionally get a row index.

Rows are searched as rows

Prose chunking is wrong for tables. A 1,000-row sheet cut into windows hands the model fragments of unrelated rows and it blends them — asked for an HDMI cable's supplier it once returned a product id belonging to Golf Tees, with a supplier and reorder point that were never in the same row as each other. Matching rows are now returned verbatim with their header and nothing adjacent. Nine of nine facts correct on retest, zero invented.

Four rules that each took a failure to learn

  • Rarity, not every word. "reorder" and "supplier" are column headings appearing in no row; "1031" appears in exactly one.
  • Two terms must land, not one. A single coincidental "68" in an inventory dragged thirty product rows into a question about school policy.
  • Plurals fold to singular. The two-term rule immediately broke what it was meant to protect — the sheet says "Cable", the question said "cables", one term landed, every HDMI row discarded.
  • Weak passages are dropped. Anything under two fifths of the best match. Before this, a question about HDMI suppliers was handed two blocks of an unrelated macOS-vs-Windows PDF, which the model had to read and reason past — and often ran out of room doing so.

The model is told the shape of a sheet

Not only column names but: which columns hold few enough distinct values to list them all (Stock Status contains only: In Stock, Low Stock), which headers are real datetimes rather than text, and which columns repeat as families (Purchased From 1..10 pairing with Purchase Qty N, which must be stacked before grouping). Each of these fixed a real failure.

09Writing and running code

The most valuable behaviour in the project

When the answer is a number, it writes a program rather than counting by eye — and shows you the program. The model is unreliable at arithmetic across rows; code that reads the file is exact. This turns the worst weakness into the most trustworthy behaviour, and it is the honest answer when anyone asks how they can know it is right.

Generated code is repaired before it runs

Three classes of slip recur, and each is cheaper to repair than to explain. All are checked against code that was already correct, so nothing valid is altered.

SlipExampleRepair
Filename slightly wrong01_20Retail_Inventory.xlsxMatched against files that exist; closest match substituted
Method without bracketsdf.loc[df['v'].idxmin]Brackets added for a closed list of pandas methods. Properties (.shape, .values) untouched
Regex literal not rawsuffix='\d+'Short literals carrying a regex escape made raw

A program that still fails is shown its own traceback and given one attempt to correct itself. That is not always enough — shown the bracket error, the model made the identical mistake a second time, which is why the mechanical repair exists as well.

10Teaching and execution

The original thesis, and it now runs end to end.

Recording

AT-SPI events, not mouse coordinates. A step reads focused [entry] "District" in window "Applicant Registry". This is what separates it from a macro recorder, which replays coordinates and shatters when a window moves.

The finding that shaped the recorder

LibreOffice emits no text-changed event for cell entry. None. The value a clerk types into a spreadsheet — most of the job — never reaches AT-SPI. The recorder therefore watches the keyboard as well and assembles keystrokes into whole entries, held rather than logged per keystroke: eleven single-character events say far less than one step reading typed "No - below 65%" into Cell I4.

Synthesis

A trace becomes a numbered, editable, plain-language procedure. A real lesson — marking exam eligibility by hand in Calc — produced the right cells and values: I1 "Exam Eligible", I2 "Yes", I4 "No - below 65%", I9 "Principal - medical certificate".

Execution — vm/executor.py

Reads the text of each step, not the target field: the target recorded against a spreadsheet step is usually the sheet, not the cell, because that is what had focus. Four actions are supported, and they are the four the lessons actually contain:

ActionHow
goto a named cellThrough the Name Box — one control, always present, always in the same place, where a cell may be scrolled out of view with no usable position
type a valueKeyboard, then verified by looking for the value in the accessibility tree
press a named controllocate.py, which raises the owning window first
open an applicationA fixed list, not an arbitrary command

Run it two ways:

python3 executor.py <trace-dir>         # the plan, no action
python3 executor.py <trace-dir> --run   # actually do it
Measured on the real recorded lesson

8 of 17 steps performable — and the 8 are exactly the substantive ones: go to I1, type "Exam Eligible", go to I2, type "Yes", go to I4, type "No - below 65%", go to I9, type "Principal - medical certificate".

The 9 it refuses are recorder noise: "Navigate to the main panel", "Navigate to the next applicant's row", and three steps of someone dismissing a save dialog. Refusing those rather than guessing is the design. A model this size guessing at an unrecognised instruction is how an apprentice confidently files the wrong thing, and a refusal you can read beats an action you cannot.

Still to do: wire the executor to the "Run it" button in shishya_app.py, which currently says the executor is not built. And run --run against a live Calc to confirm the actions land, which has not yet been done.

11Findings

Everything else is reactive: you ask, it answers. Findings is the opposite — it reads your spreadsheets and goes looking for what nobody thought to ask about. Six checks, each a bounded brief turned into a program, run, and reported with the program attached so every finding is checkable.

The rule that makes it useful

The first full run was not good enough to show anyone: 8,254 "outliers", sku: 10S reported as a duplicate identifier (it is a pack size), 3,455 items "stopped moving". That is a dump, not a finding.

Every brief now inherits one rule: never more than ten lines, ranked by what makes a thing matter, and say how many there were in total. A finding is only useful if it is short and someone can act on it.

One check is written, not generated

The near-duplicate name check — the one that found the supplier counted twice — reported zero, because the spellings are spread across the ten Purchased From columns and it was grouping each column separately. Told to stack families first, the model then failed twice with increasingly inventive pandas.

So it is written: stack families, normalise case and whitespace, group, keep spellings with at least five rows each, rank by rows affected. 26 findings in two seconds with no model call, against roughly three minutes and two failures before. The app runs a built-in where one exists and generates a program otherwise — the model where the shape varies, code where it does not.

12The permission model

Four independent controls, each measured rather than assumed.

Egress — three states, not two

Locked (default)BrowsingUnlocked
The model✓✓✓
Web (DNS, 80/443)✗✓✓
Anything else✗✗✓

Browsing is a mode you switch on, written to the ledger when it changes, and the sandbox cannot grant it to itself — no sudo, and the rules live outside its reach. Tested: with browsing on, a connection to port 22 was still refused while the web worked.

The claim was never that this can never reach the internet. It is that it cannot unless you say so, and when you do it is in the log.

The other three

  • The mount list. The only writable window is shared/. Everything else on the Mac does not exist from inside.
  • No sudo. The clone is unprivileged even within its own sandbox.
  • Rollback. APFS clone; 12 seconds; the environment survives and the clone's work does not.

The panel's terminal

Runs inside the sandbox as clone, never on the Mac. Verified: whoami returns clone, sudo -n true demands a password, and ls /Users reports no such directory. Every command is written to the ledger before it runs, so one that hangs still leaves a record of what was asked.

13Design language

Swiss-technical, after a reference the owner supplied: a cool grey gradient ground, pure black hairlines, uppercase letterspaced labels with a great deal of air, square corners, and no colour at all.

Two decisions follow from removing the palette, and both are load-bearing:

  • Emphasis is inversion. A control that is on is a solid black block with white type — the strongest signal available once hue is gone.
  • Refusals in the ledger are inverted blocks, not red rows. The audit trail is the most important thing on the panel, so it gets the strongest treatment the language allows — and unlike colour it survives being photographed, projected badly or printed in mono.

Destructive controls could not be red either, so they are marked structurally: a heavier rule under Roll back, dashed under the reversible pair. A three-state appearance switch (light / dark / auto) sits in the header; auto is the absence of the attribute, which is what the stylesheet already keyed on.

An earlier pass rendered the panel in Apple's language — SF Pro via -apple-system, translucent toolbar, system blue. It was replaced at the owner's request. If it is ever wanted back it is in commit 0128786.

15Known limits

Do not demonstrate
  • Asking it to count or filter across rows in its head. It named two of three students below an attendance threshold, twice out of three runs, and once invented a percentage. Route to code — the shortcut does this automatically, but phrasing that dodges the keywords will slip through.
  • Transcribing an existing table into a spreadsheet. Asked to copy a mark sheet it filled all 48 numeric cells with the word "maths" — a repetition loop under schema-constrained generation. Building a table from prose is fine; copying one is not.
  • Executor --run against live Calc. The plan is verified; the actions have not been performed end to end.

Rough edges to know about

  • Clicking inside the sandbox is unreliable. Stale noVNC connections swallow button releases, so windows raise and tooltips show while nothing activates. Drive from the panel; Fix input rebuilds the display in five seconds without closing apps.
  • The VM stops when the Mac sleeps. Every time. ./demo.sh recovers.
  • Ollama is an app and quits. demo.sh restarts it.
  • Filenames uploaded before 21 August are mangled (01_20Retail_20Inventory.xlsx was 01 Retail Inventory.xlsx). The encoding bug is fixed; old files were never renamed.
  • A cloud model is installed — deepseek-v3.1:671b-cloud. Filtered out of the Models picker so it cannot be chosen by accident, but it exists. Selecting it would destroy the entire sovereignty claim.
  • Qt WebEngine needed AppArmor's namespace restriction relaxed inside the VM for the browser to render. A real control loosened, defensible only because the VM is the boundary.

16The failure ledger

The most valuable section. A design can be re-derived from the code; these cannot. Each cost real time and several were diagnosed wrongly first.

A syntax error stopped the entire panel

Symptom: nothing worked. Every endpoint returned 200, all fourteen checks were green, and the page did nothing.

Cause
The terminal and theme blocks were inserted by anchoring on refresh();, and Python's str.replace replaces every occurrence unless told otherwise. That string appears three times, so the blocks landed inside send() and inside guard()'s finally clause as well, each time leaving an if followed by a const.
Two wrong turns
A bracket counter reported an unclosed parenthesis — it did not know a regex literal from an expression. And the console kept showing the same error after the fix; old messages persist. It was only confirmed by importing the module dynamically.
Lesson
A syntax error is invisible from the outside — every machine-side diagnostic reports perfect health. Check the browser console first when a page misbehaves, and always pass count=1.

Input died three times

Symptom: windows raise, tooltips appear, nothing activates. Looks exactly like a frozen app.

Cause
Stale noVNC connections accumulate — eight websockify children at worst — and button releases stop being delivered. GTK focuses on press and fires on release, so every control took focus and did nothing.
Wrong theories, in order
A GTK bug; window stacking; a stuck mouse button; occlusion. All wrong. What identified it was noticing AT-SPI doAction worked while pointer clicks did not.
Lesson
When a UI looks dead, find a second input path and try it. If one works and the other does not, you have localised the fault in one step.

Rollback wiped the entire sandbox

Symptom: after pressing Roll back, no GTK, no pandas, no apps — every window dead.

Cause
The clean snapshot was taken before the desktop, apps and libraries existed. It did exactly what it was asked and restored a bare Ubuntu.
Lesson
"Undo the work" and "undo everything ever built here" were the same button and nothing said so. A destructive control must name what it will destroy. The confirmation now shows the snapshot's date.

The egress lock strangled the control panel

Symptom: panel bound correctly, listening, timing out on every request.

Cause
sudo inside the sandbox looks up the machine's own hostname. /etc/hosts had no entry, the egress lock blocks DNS, and it waited for the timeout — 10.017 seconds per sudo. The panel polled every three seconds.
Fix
One line: 127.0.1.1 lima-shishya. 10.017s → 0.003s.
Lesson
Locking the network makes everything that quietly expected a network slow rather than broken, and slow is far harder to diagnose.

Confident fabrication on tables

Symptom: asked for the HDMI cable's supplier, it returned product ids belonging to a USB Cable and to Golf Tees.

Cause
1,000 rows chunked into overlapping text windows. It saw fragments of unrelated rows and blended them.
Lesson
Retrieval designed for prose is actively dangerous on tables. Return whole rows with their header and nothing adjacent, so there is nothing to blend.

It reported nothing was low on stock, across 149 low-stock rows

Symptom: plausible pandas, plausible output, completely wrong.

Cause
It filtered Stock Status == 'Low'; the sheet says 'Low Stock'. It knew the column names because we told it, and guessed the values because we had not.
Lesson
Give the model the vocabulary, not just the schema. And note this was only catchable because the code was on screen.

Four of eight real questions died on the same line

Symptom: 'datetime.datetime' object has no attribute 'startswith'.

Cause
Month column headers are real datetimes, but printed into the prompt as 2025-04-01 00:00:00 they look like text.
Lesson
Anything rendered into a prompt is being described, and a faithful repr can still be a misleading description.

Measurements that lied, three times

What happened
pgrep -c … || echo 0 printed both its own count and the fallback, inventing a duplicate process. ps %cpu reports the average since process start, not current usage, and showed a working optimisation as having no effect. A /proc sample window straddled the moment an answer arrived, so a feature that worked appeared not to.
Lesson
Suspect the instrument before the code. Two of these produced confident wrong reports that had to be retracted.

Smaller ones worth not repeating

  • {{.Dir}} in Lima is the instance directory, not the config file's — both mounts pointed at the wrong place.
  • useradd -m leaves the home root-owned when the directory already exists as a mount parent.
  • pkill -f "shell/desktop.py" never matched because provisioning cds first — four desktops stacked up unnoticed.
  • int(1000 / self.fps or fps) parses as (1000 / self.fps) or fps — divides by zero instead of falling back.
  • self.boxes initialised after the loop that fills it — desktop crashed with every icon missing.
  • The upload handler never decoded the percent-encoded filename, mangling every file with a space in its name.
  • Backgrounding through limactl shell never detaches cleanly; use a systemd unit or setsid with stdin closed.
  • A range-replacement between two markers deleted a function; Python still parsed and the app caught the error per click.
  • The ledger rendered 94 entries into zero height — a flex child with no min-height. It was rendering into nothing, which looks identical to not rendering.
  • A GTK stylesheet is a bytes literal; an em dash in a comment breaks the whole shell.
  • Binding only to 127.0.0.1 means localhost fails, because macOS resolves it to ::1 first.

Two operating rules

Drive everything from the panel. Never click inside the clone's screen. Every action needed is a panel button, and the panel has never failed.

If the panel disagrees with ./demo.sh check, believe demo.sh. It reads the machine directly; the panel reads it over HTTP and can be showing a stale page. Reload settles it.

18Demonstrating it

  1. Open on the problem, not the product. Staff paste confidential records into cloud AI; once it leaves the building you cannot control or audit it.
  2. Drop their own documents on the panel and press Use as sources. The chat notices and says what it read.
  3. Ask a question they actually get asked. Then let them choose the next one — that is what stops it reading as rehearsed.
  4. Ask for something counted — it writes a program and shows it. Say plainly that it is unreliable at arithmetic by eye, which is exactly why it writes code.
  5. Run Findings. The duplicate-supplier result is the strongest thing this project does.
  6. Ask it to make a document and open the file.
  7. Prove the network claim. Point at the egress readout, then curl from inside the sandbox and watch it return nothing while the model keeps answering.
  8. Open the ledger and point at the inverted refusal line.
  9. Roll back and watch the last ten minutes cease to exist.
If something fails live

Own it immediately: "That is wrong, and this is exactly why the log and the undo button exist." Then show the source it read. The audience is judging whether you are honest about limitations, and a demonstration that goes perfectly teaches them less about you than one that does not.

19What to build next

  1. Finish the executor. Wire it to the Run button in shishya_app.py, and run --run against live Calc. The plan is verified; the doing is not.
  2. Ask-when-unsure. Detect low confidence, pause, ask, fold the answer back into the procedure. This is what makes "apprentice" true rather than a metaphor, and it turns the one-demonstration weakness into the pitch.
